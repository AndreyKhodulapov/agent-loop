# Что вообще нужно лично мне

- реализация планируется для claude cli (подписка max) с возможностью расширения на вызов других cli. 
- В решении задач постоянно повторяется один и тот же цикл: декомпозиция задачи агентом, открытие новой сессии с агентом - передача ему очередной задачи - проверка выполненного (так до окончания задач). Ревью всей ветки по окончании, фикс обнаруженного, повторное ревью до исчезновения критических проблем. Нужно автоматизировать эти рутины. 
- для этого нужна подробная декомпозиция задачи с составлением артефакта (plan.md) вплоть до учета размера диффа, по хорошему не должен превышать 1000 строк на коммит включая тесты. Критика плана со стороны агента с незаполненным контекстом. Обсуждение по вопросам должно осуществляться со мной на этом этапе, а дальще по хорошему идти без моего вмешательства. Я хочу отсматривать только итоговый дифф перед МР, вот цель. 
- запуск агентного цикла в сохранением состояния в файл progress.md. На каждую задачу открывается новая сессия claude c передачей контекста задачи. Нужно придумать как уменьшить загружаемый контекст - передавать не весь прогресс plan.md в например только декомпозированную задачу. 
- альтернатива - держать состояние в условной SQLite (иной БД), но не ясно как передавать ее между 2-мя независимыми машинами, если пушить в удаленный гит репозиторий - он раздуется до неприличных размеров, это бинарь.  Подумать вообще хорошее ли это рещение или md файлы проще. но их количество растет, искать по ним что-то очень неудобная история. Плюс нужна валидация коммит сообшений и в целом что-то структурированное проще делать в БД. 
- прогон тестов и форматтера - отдельным этапом без вмешательства LLM. Упало - вызвать модель с контекстом для правки. 
- коммит - средствами терминала, без участия LLM. LLM может составлять сообщение для коммита, короткое и без указания себя в качестве соавтора. Отсутствие соавторства должно ВАЛИДИРОВАТЬСЯ после чего коммит осуществляется вызовом bash функции.  
- по окончании задачи подъем сервиса средствами командной строки, вызов эндпоинта если это апи по curl, запись успешности (самое сложное сделать это без LLM, потребуется стандартизация разрабатываемых сервисов либо DOD который можно передать в eval)
- нужен строгий учет расходуемых токенов. Работащая сессия не может выжирать 5 часовую сессию. По хорошему у запущенной сессии должен быть лимит, определяемый так, чтобы невозможно было достичь 5-часового окна раньше, чем в поледний его час, а в день - превысить процент потребления определяемый как (номер для недели) / 7 * на недельный лимит. Нужно учесть что одновременно могут быть запущены несколько циклов и расчет их подребления должен осуществляться суммарно, то есть по данным самого 
- системный выход ctrl+c из задачи ведет сначала к сохранению всешл прогресса и только потом к остновке процесса. Это важно. 
- В терминале должны быть логи что происходит и на каком это этапе. 
- внутри цикла ТЗ, команды и промпты могут передаваться на английском (если это удобнее), но я должен иметь возможность настроить на каком языке будет писаться документация и спецификация (тут опционально - русский и английский, у меня мультиязычные проекты)
- есть возможность human-in-the-loop то есть если у агента есть сложности позвать оператора решить вопрос, но таких ситуаций должно быть как можно меньше, все должно обсуждаться на этапе проектирования. 

Общий флоу как я его вижу - серия bash скриптов-надстроек над claude-cli. Я передаю задачу как файл или ввожу ее в терминал дальше флоу идет без моего участия. Можно вывести мне финальный согласованный план (утвержденный планировщиком и критиком), чтобы я пробежался по нему. У планировщика и критика есть не более 2-х итераций на обсуждение, у ревью не более 2х итераций на правки, после чего составляется отчет с которым я знакомлюсь.
